# Skim Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `skim(text, maxWords)`, a pure function that reports a whitespace word count, whether that count is over the cap, and a headline clipped to the cap.

**Architecture:** One module, one exported function. Tests import it directly. No I/O.

**Tech Stack:** TypeScript, `bun:test`, no runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-27-skim-design.md`

## Global Constraints

- TypeScript. Tests use `bun:test`. No runtime dependencies.
- Words split on whitespace. A hyphenated token is one word.
- Empty or whitespace-only text: `words` 0, `status` `"ok"`, `headline` `""`.
- `status` is `"over"` only when `words > maxWords`.
- `headline` collapses whitespace to single spaces. A clip ends with one `…`. A fit has no ellipsis.
- Otherwise throw `TypeError` with message `maxWords must be an integer greater than or equal to 1`.

## Review Focus

- A `NaN` cap throws `TypeError` — a caller who divided by zero should not get a headline. Test on Task 1.
- Whitespace-only text counts as empty — a blank chunk is not one word. Test on Task 1.
- A hyphenated token stays one word — `well-known` is not two words. Test on Task 1.
- The ellipsis is the single character `…`, not three dots — the constraint names that character. Test on Task 2.
- A cap equal to the word count does not clip — "over" means greater than, not greater than or equal. Test on Task 2.

## File structure

- `src/skim.ts` — `skim` and the `SkimResult` type. Nothing else.
- `tests/skim.test.ts` — the behaviors below. Task 2 appends tests; it does not rewrite Task 1's assertions.

### Task 1: Count, status, and validation

**Files:**
- Create: `src/skim.ts`
- Test: `tests/skim.test.ts`

**Interfaces:**
- Consumes: nothing
- Produces: `skim(text: string, maxWords: number): SkimResult` where `SkimResult` is `{ words: number; maxWords: number; status: "ok" | "over"; headline: string }`. After this task, `headline` is the whitespace-collapsed text with no clipping. Task 2 changes clipping only.

- [ ] **Step 1: Write the failing test**

```ts
import { expect, test } from "bun:test";
import { skim } from "../src/skim.ts";

test("empty text is zero words and ok", () => {
  expect(skim("", 5)).toEqual({ words: 0, maxWords: 5, status: "ok", headline: "" });
});

test("whitespace only is empty", () => {
  expect(skim("  \n\t ", 3)).toEqual({ words: 0, maxWords: 3, status: "ok", headline: "" });
});

test("counts words under the cap", () => {
  expect(skim("alpha  beta", 5)).toEqual({
    words: 2,
    maxWords: 5,
    status: "ok",
    headline: "alpha beta",
  });
});

test("a hyphenated token is one word", () => {
  expect(skim("well-known path", 5).words).toBe(2);
});

test("status is over when the count exceeds the cap", () => {
  const result = skim("one two three", 2);
  expect(result.words).toBe(3);
  expect(result.status).toBe("over");
  expect(result.maxWords).toBe(2);
});

test("rejects a cap that is not an integer >= 1", () => {
  expect(() => skim("one", 0)).toThrow(TypeError);
  expect(() => skim("one", 1.5)).toThrow(
    "maxWords must be an integer greater than or equal to 1",
  );
  expect(() => skim("one", Number.NaN)).toThrow(TypeError);
});
```

- [ ] **Step 2: Run test to verify it fails**

Run: `bun test tests/skim.test.ts`
Expected: FAIL because `skim` is not implemented (a thrown `not implemented`, or a wrong return), not because of a syntax error.

- [ ] **Step 3: Implement `skim(text: string, maxWords: number): SkimResult` in `src/skim.ts`**

Validate `maxWords` first. Split trimmed text on whitespace. Return the count, the same `maxWords`, `"over"` when the count is greater, and the collapsed words joined by single spaces (no clip yet).

- [ ] **Step 4: Run test to verify it passes**

Run: `bun test tests/skim.test.ts`
Expected: PASS, 6 tests.

### Task 2: Clip the headline

**Files:**
- Modify: `src/skim.ts`
- Test: `tests/skim.test.ts`

**Interfaces:**
- Consumes: `skim(text: string, maxWords: number): SkimResult` from Task 1
- Produces: the same signature. `headline` is now clipped to `maxWords` words, with one `…` only when words were dropped.

- [ ] **Step 1: Write the failing test**

Append:

```ts
test("clips the headline to the cap with one ellipsis", () => {
  expect(skim("alpha beta gamma", 2).headline).toBe("alpha beta…");
});

test("does not add an ellipsis when the text fits", () => {
  expect(skim("alpha beta", 5).headline).toBe("alpha beta");
});

test("an exact cap does not clip", () => {
  expect(skim("alpha beta", 2).headline).toBe("alpha beta");
  expect(skim("alpha beta", 2).status).toBe("ok");
});

test("collapses whitespace and then clips", () => {
  expect(skim("  alpha   beta\tgamma ", 2).headline).toBe("alpha beta…");
});
```

- [ ] **Step 2: Run test to verify it fails**

Run: `bun test tests/skim.test.ts`
Expected: the clip test FAILs because the headline is still the full collapsed string `alpha beta gamma`. The Task 1 tests still pass.

- [ ] **Step 3: Clip in `skim`**

When there are more words than `maxWords`, `headline` is the first `maxWords` words joined by spaces, plus `…`. Otherwise it stays the collapsed text.

- [ ] **Step 4: Run test to verify it passes**

Run: `bun test tests/skim.test.ts`
Expected: PASS, 10 tests.

- [ ] **Step 5: Commit**

```bash
git add src/skim.ts tests/skim.test.ts
git commit -m "feat: clip the skim headline on a word boundary"
```
